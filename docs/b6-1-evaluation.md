# B6-1. 평가문항

## 항목 1 — 인프라 구성 및 외부 접속 검증

- VPC, Public Subnet, Internet Gateway, Route Table(`0.0.0.0/0 → IGW`)이 구성되어 있는가?
- EC2에 SSH로 접속 가능하며, 웹 서버가 실행 중인가?
- 보안 그룹 인바운드가 **필요한 포트만** 허용하며, SSH(22)가 특정 IP로 제한되어 있는가?
- 외부 접속이 아래 방식 중 1개로 검증되는가?  
  제출자가 선택한 방식으로 확인한다.
  - **방식 A:** 브라우저에서 `http://<퍼블릭IP>` 접속 시 페이지가 정상 로딩되는가?
  - **방식 B:** `GET /health` 호출 시 HTTP 200과 고정 응답이 확인되는가?
- 리소스 정리 체크리스트에서 최소 5종(`EC2`, `EBS`, `EIP`, `IGW`, `VPC`)의 정리 완료를 확인할 수 있는가?

## 항목 2 — 구조 및 설계 설명

- **외부 → IGW → Subnet → EC2**로 이어지는 네트워크 흐름을 아키텍처 다이어그램을 기준으로 설명할 수 있는가?
- 보안 그룹 규칙을 어떤 기준으로 최소화했는지, 허용한 포트와 허용하지 않은 포트를 구분해 설명할 수 있는가?
- 외부 접속 검증 방식으로 A 또는 B 중 무엇을 선택했으며, 해당 검증을 위해 무엇을 어떻게 구성했는지 설명할 수 있는가?
- 실습 리소스를 추적하고 정리하기 위해 사용한 기준인 태그, 이름 규칙, 체크리스트를 설명할 수 있는가?

## 항목 3 — 핵심 원리 이해

- Public Subnet Route Table의 기본 경로인 `0.0.0.0/0 → IGW`가 필요한 이유를 설명할 수 있는가?
- Security Group과 IAM의 책임 범위 차이를 설명하고, 최소 권한 원칙이 필요한 이유를 설명할 수 있는가?
- SSH(22) 또는 DB 포트를 `0.0.0.0/0`로 열면 안 되는 이유와 안전한 대안을 설명할 수 있는가?
- 트러블슈팅에서 **가설 → 검증** 순서를 유지한 이유와 로그 및 근거를 어떻게 활용했는지 설명할 수 있는가?

## 항목 4 — 문제 해결 및 확장 대응

- 외부 접속이 되지 않을 때 다음 순서로 점검하는 이유와 방법을 설명할 수 있는가?
  1. 라우팅
  2. Security Group
  3. 퍼블릭 IP 또는 DNS
  4. 서버 프로세스 및 로그
- IAM 권한 부족으로 작업이 실패했을 때 권한을 무작정 확대하지 않고, 필요한 최소 권한 범위를 찾아가는 방법을 설명할 수 있는가?
- 트래픽 증가로 인스턴스를 2대로 확장해야 할 때 현재 구조의 병목을 판단하고, ALB(Application Load Balancer) 등 추가할 구성 요소를 설명할 수 있는가?
- Billing에 예상하지 못한 비용이 발생했을 때 우선 의심할 리소스와 비용을 추적하고 정리하는 절차를 설명할 수 있는가?
